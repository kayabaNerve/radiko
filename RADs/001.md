# Radiko

In order to ensure clarity on the project's purpose, aligning contributors on
how to move forward, we aim to establish the following definitions and
procedures to begin this undertaking with.

### Definitions

#### "bootstrapped"

A "bootstrapped" binary is a binary built almost entirely from source, all the
way down to a singular small precompiled binary seed of size no more than a few
hundred bytes.

#### "source"

"source", "source code", is content by a human which may be transformed by an
automated process, program, or machine (such as a compiler) in order to output
an alternative (derivative or approximate) representation.

#### "binary"

"binary", "binaries", "binary blobs", "blobs" refers to any content output by
an automated process, program, or machine (such as a compiler), the opposite of
"source".

#### "constants"

"constants" refers to values and definitions which may or may not be defined by
algorithms, specifications, or standard. These values MAY appear as opaque
blobs but are considered "source"
_unless defined via a transformation from "source"_. This allows the definition
of a series of mathematical constants, even when their origin is opaque, as
necessary to implement specifications. However, if the constants were found via
a computer-assisted search, and have been specified as the output of such a
search (with source), the search program is the source and the constants a
binary blob.

#### "reproducible"

A process which, when repeated, yields a consistent result. The interpretation
of this SHOULD be independent of the host and as many variables as possible.

### Goals

The goals of the Radiko Bootstrap are to provide a bootstrap for reproducible
builds of Monero, Cuprate, and Serai. After achieving reproducible builds for
Monero, Cuprate, and Serai, the goals of Radiko become solely its maintenance
and quality assurance.

### Architecture

Radiko is premised on
[Open Container Initiative](https://opencontainers.org) containers. Being
initially forked from [StageX](https://codeberg.org/stagex/stagex), it inherits
the literal `Containerfile`s and build tool found within the StageX project (at
the time of its fork). This includes:

- A bootstrap derived from
  [`live-bootstrap`](https://github.com/fosslinux/live-bootstrap)
- [LLVM](https://llvm.org)
- [musl](https://musl.libc.org) with hardened
  [mimalloc](https://github.com/microsoft/mimalloc)

These components are agreed with and should be kept, barring a
Radiko Architecture Document (RAD) to replace them.

### Minimal Footprint

As part of ensuring the project is feasible to maintain, with increased quality
assurance as time goes on (review, testing, and confidence in the lack of
binary blobs), the project is explicitly scoped to solely Monero, Cuprate, and
Serai. All included packages MUST either be:

- An explicit dependency of one of these three projects
- An associated project or service which has been approved via a RAD
- A component useful to the Radiko bootstrap itself, as LLVM is

### Radiko Architecture Documents (RADs)

RADs are the primary way the project is defined. Major design decisions and
changes should be recorded via RADs, ideally only after a comment period, with
all maintainers' approval. Anyone may contribute a RAD for consideration.
